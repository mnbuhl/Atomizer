<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Callback execution inside transaction | The callback passed to ExecuteInLeaseAsync runs with an open ReadCommitted transaction — any exception from the callback causes DisposeAsync to rollback automatically |
| Lock timeout | CancellationToken from StartTransaction is linked to the outer cancellationToken — timeout does not swallow the outer cancellation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Denial of Service | ExecuteInLeaseAsync lock timeout | mitigate | LockTimeout defaults to 30s; StartTransaction wraps timeout in linked CTS — caller never blocks indefinitely |
| T-04-02 | Tampering | Transaction rollback on callback exception | mitigate | DatabaseTransactionLeasingScope.DisposeAsync rolls back on any exception rethrown from the await using block — no partial commits |
| T-04-03 | Elevation of Privilege | queue parameter unused | accept | The queue param is part of the interface contract for future provider specialization; EF Core uses per-DbContext connection locking which is already scoped per DI scope |
</threat_model>
