XML doc rules (from CLAUDE.md and PATTERNS.md):
- `<summary>` on every public type and member. One prose sentence ending with a period.
- `<param name="x">` for every parameter. Starts with capital letter, ends with period.
- `<returns>` for non-void returns:
    - Task (no result): "A task representing the asynchronous operation."
    - Task<T>: describe what T is directly (e.g. "The unique identifier of the inserted job.")
    - non-Task value: describe the value

- `<remarks>` goes INSIDE the `<summary>` block (not as a sibling after `</summary>`).
- Do NOT add `<exception>` tags — existing docs have none.
- `cancellation` is the parameter name on IAtomizerClient methods (public API convention).
- `cancellationToken` is the parameter name on all other APIs (storage, internal).
- No `<inheritdoc/>` on non-override members.
- `<see cref="TypeName"/>` when referencing another type inline.
